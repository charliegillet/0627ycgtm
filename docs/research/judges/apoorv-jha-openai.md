## Codex workflow tips for shipping fast (24h)

From OpenAI's Codex best-practices docs:

- **Write `AGENTS.md` first.** Put durable rules there (test commands, paths to avoid, commit style, "what to do before opening a PR"). Every Codex session in the repo auto-loads it; Codex is trained to run the tests named in AGENTS.md before declaring "done." Don't bloat prompts with rules that belong in AGENTS.md.
- **One thread per task, not per project.** Per-project threads bloat context and degrade results.
- **Run agents in parallel, but scope them.** Assign well-defined, non-overlapping deliverables ("what to produce and where to write it") so parallel agents don't collide. Delegate long-running pieces to **Codex Cloud** while you keep building locally.
- **Reasoning effort:** default **medium**; bump to **high/xhigh** only for the hardest logic; **low** for quick edits - manage latency deliberately.
- **TDD loop with Codex:** write failing tests, commit them as a checkpoint, tell Codex to implement until green and **not to touch the tests.**
- **Turn the repeated bit into a Skill** (`SKILL.md` + name + when-to-trigger). Use Record & Replay or the `skill-creator` to scaffold. Great for the standardized "brief/score" generator.
- **Wire the Docs MCP** so Codex pulls correct API schemas while building:
  - Claude Code: `claude mcp add --transport http openaiDeveloperDocs https://developers.openai.com/mcp`
  - Cursor / VS Code: add `https://developers.openai.com/mcp` to `mcp.json` (read-only docs search + page content).

## Idea hooks for the hackathon

1. **"Custom signal SDR" (most on-thesis):** Pick ONE non-bought signal (e.g., a prospect shipping a competitor integration, a new job posting, a GitHub activity spike, a pricing-page change). DETECT via web search/connectors → ENRICH via a research agent (Clay-style, the OpenAI-Clay case study is the blueprint) → SCORE via **structured outputs** → ACT by drafting + sending outreach (Gmail connector). Built on **Agents SDK with handoffs + guardrails** for technical-complexity points.
2. **Re-skin OpenAI's own sales-meeting-prep agent** around a *custom* trigger instead of "tomorrow's calendar" - e.g., "any account whose docs/site changed in the last 90 days." Differentiates from the cookbook while reusing its proven plumbing.
3. **Realtime voice "deal copilot"** that listens to a (mock) sales call, pulls live enrichment, and surfaces next-best-action on screen - high coolness for the 3-min video via the Realtime API.
4. **Computer-use "ACT" closer:** agent that logs the scored lead + drafted sequence directly into a real CRM UI on camera - visceral end-to-end proof, if time allows.
5. **RocketRide tie-in (10% objective):** model the whole DETECT→ENRICH→SCORE→ACT flow as agent/tool nodes; the OpenAI Agents-SDK handoff pattern maps cleanly onto RocketRide's agent-node orchestration.
6. **Mentor play:** pull Apoorv aside early, frame the build as OpenAI-native (Codex + Agents SDK + structured outputs + Docs MCP), and ask which Cookbook pattern they'd reuse - costs nothing, buys goodwill and a better demo.
